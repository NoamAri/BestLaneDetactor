Lane Intel Code Map

The project turns motorway video into a list of vehicles, each with an ID, a class, a box in every frame, a speed, a direction and a lane, and shows it on top of the video so you can check it frame by frame. Two videos are in so far: a 4K drone clip of the A50 in Milan (MiTra dataset, with ground truth) and an uploaded clip filmed from a building. The goal: measure each lane and say which one is measurably fastest.

Every stage reads files written by the stage before it. Detection runs once and saves every box; tracking reads those boxes, so tracker settings are compared on identical input in seconds and nothing downstream reruns the model.

3 · Inside the viewer

The video decides which frame you are on

The viewer never assumes a seek worked. Whatever you press, it asks the video to move, waits for the video to report the frame it actually painted, and only then draws boxes for that frame. This loop is what fixed the "boxes on empty road" bug.

4 · Pixels and time

One coordinate system on disk, four images on the way

5 · What the files contain

Data formats between stages

detections.parquet · written by detect.py

One row per box YOLO found, confidence ≥ 0.05, no IDs: t, frame_idx, cls, cls_id, conf, x1, y1, x2, y2 (full-frame pixels). Next to it, .meta.json records the video, window, band, detector settings, device, runtime, box counts and library versions.

points.parquet · written by the tracking package

ColumnMeaning
tseconds since the clip's first frame
frame_idxframe number in the clip (0 = flight time 5:00.000)
track_idByteTrack's ID; the same vehicle keeps it across frames
cls, cls_idCOCO class name and number: car 2, motorcycle 3, bus 5, truck 7
confYOLO confidence, 0.25–1
x1 y1 x2 y2box corners, full-frame pixels
x_px y_pxbottom-centre anchor point, full-frame pixels
x_w y_wworld metres, empty until calibration (phase 2)
lane_framelane of this box (index into the camera's lanes file), −1 outside every lane
lane_tracklane of the vehicle: the most frequent lane of its boxes
raw_track_idthe tracker's own ID (differs from track_id only if stitching joined pieces)

tags_<variant>.json · for the browser, one per tracker

One array, one record per line, integers only to keep it at about 3 MB:

[frame, track_id, class_index, conf_%, x1, y1, x2, y2] [449, 11, 1, 79, 2105, 1316, 2184, 1351]

meta.json

fps, clip_offset_s, frame_first, frame_count, crop (which part of the full frame the video shows), video_size, classes, model name, and variants: per tracker its label, note, quality numbers and one summary per track (first and last frame, observations, majority class, mean confidence, duration, image motion in px/s, mid-image start/end flags and positions).

report.json · tracking experiment

Per variant: the resolved config, the quality summary and guard verdicts; plus the selected variant, the thresholds, the selection rule and the detections' provenance.

6 · Running it

The commands, in order

run.py (any OS) and the Makefile (Linux, macOS) call the same modules with the same venv. Each step skips work whose output already exists.

python run.py setup # .venv, packages, yolo26s.pt python run.py clip # 3-min clip from the remote zip python run.py detect # YOLO once on 0-30 s (slow) python run.py tune # all trackers + report (seconds) python run.py track # chosen tracker -> points python run.py lanes # lanes + lane per vehicle python run.py viewer # all videos -> data/out/viewer/ python run.py serve # http://localhost:8000 python run.py pages # copy to docs/ python run.py test # 48 tests # another camera: add --cfg configs/<camera>.json

7 · Tracking experiment (steps 0–2)

Fewer broken tracks without more wrong merges

Fifteen tracker settings ran on the same saved detections. The score is fragmentation: tracks that start or end in the middle of the image, which on this road can only be breaks. Two guards reject a setting that gets there by merging different vehicles (identity jumps) or by dropping boxes (coverage). The rule, and how the held-out window decides, were committed to git before the results.

Bars: change in fragmentation against that window's baseline (478 and 547), drawn at one scale (2.6 px per percentage point). Green bars passed both guards on that window, grey failed. Identity jumps: guard limit about 25 on each window. Selected row highlighted. Full tables: notes/tracking.md.

Decision

  • BoT-SORT with a loose first match (r2_botsort_first005): confident boxes continue a track at overlap × confidence ≥ 0.05; faint boxes (0.10–0.5) need 50% overlap and never start a track; 4 s memory.
  • On video it was not tuned on: 18% fewer breaks, 13% fewer IDs, half the identity errors, same coverage.

What was learned

  • Faint boxes recover partly hidden cars, but in a jam they also overlap neighbours. A video audit confirmed 8 of 8 flagged jumps were real swaps.
  • A longer memory alone barely helps: matching is by overlap, and a car that moved while hidden no longer overlaps its prediction.
  • OC-SORT cuts the most breaks, by re-linking after long gaps, but often to the wrong vehicle.

8 · Lanes and the second video

Lanes found from where vehicles drive

Cars keep to their lanes, so their paths cluster into one band per lane. The lane shape is chosen per camera by testing which family predicts held-out vehicles best, and lanes with traffic standing still are recovered from the stopped cars. Lane 1 is the leftmost lane in the direction of travel, the one next to the median.
