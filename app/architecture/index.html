Lane Intel Code Map

The project turns a 4K drone video of the A50 motorway in Milan into a list of vehicles with an ID, a class and a box in every frame, then shows that list on top of the video so you can check it frame by frame. Later phases will turn the same list into per-lane speeds and decide which lane is measurably fastest.

Every stage reads files written by the stage before it. Detection runs once and saves its results, so the viewer and future metrics never need to rerun the model.

3 · Inside the viewer

The video decides which frame you are on

The viewer never assumes a seek worked. Whatever you press, it asks the video to move, waits for the video to report the frame it actually painted, and only then draws boxes for that frame. This loop is what fixed the "boxes on empty road" bug.

4 · Pixels and time

One coordinate system on disk, four images on the way

Every box is stored in full-frame pixels of the original 3840 × 2160 video, whichever crop it was detected in. That keeps the stored data independent of how we cut or scale the picture later.

5 · What the files contain

Data formats between stages

points.parquet · written by extract.py

ColumnMeaning
tseconds since the clip's first frame
frame_idxframe number in the clip (0 = flight time 5:00.000)
track_idByteTrack's ID; the same vehicle keeps it across frames
cls, cls_idCOCO class name and number: car 2, motorcycle 3, bus 5, truck 7
confYOLO confidence, 0.25–1
x1 y1 x2 y2box corners, full-frame pixels
x_px y_pxbottom-centre anchor point, full-frame pixels
x_w y_wworld metres, empty until calibration (phase 2)
lane_framelane number, −1 until lane polygons exist (phase 2)

detections.json · for the browser

One array, one record per line, integers only to keep it at about 3 MB:

[frame, track_id, class_index, conf_%, x1, y1, x2, y2] [449, 11, 1, 79, 2105, 1316, 2184, 1351]

meta.json

fps, clip_offset_s, frame_first, frame_count, crop (which part of the full frame the video shows), video_size, classes, model name, and tracks: one summary per track (first and last frame, observations, majority class, mean confidence, duration, image motion in px/s).

6 · Running it

The commands, in order

run.py (any OS) and the Makefile (Linux, macOS) call the same modules with the same venv. Each step skips work whose output already exists.

python run.py setup # .venv, packages, yolo26s.pt python run.py clip # 3-min clip from the remote zip python run.py extract # detect + track first 30 s python run.py viewer # build data/out/viewer/ python run.py serve # http://localhost:8000 python run.py pages # copy viewer to docs/ python run.py test # 12 tests
make setup make clip make extract START=0 DUR=30 make viewer START=0 DUR=30 make serve make test
